2️⃣ Unity Client Loads Quests

Unity Client quest_engine_get

Game starts → QuestEngineManager.LoadQuests() → fetches all active quests with progress

Unity Code: 
public async void LoadQuests() {
  var (client, session) = await IVXNManager.Instance.GetValidSessionAsync();
  var payload = JsonUtility.ToJson(new GetPayload { gameId = _gameId });
  var result = await client.RpcAsync(session, "quest_engine_get", payload);
  var envelope = JsonUtility.FromJson(result.Payload);
  CurrentQuests = new List(envelope.data.quests);
  OnQuestsLoaded?.Invoke(CurrentQuests);
}

Client Model: 
public class QuestData {
  public string id, name, category;
  public QuestStepData[] steps;
  public int startedAt, completedAt, claimedAt;
  public QuestRewardPreview rewardPreview; // Only guaranteed currencies
  public bool HasUnclaimedReward => completedAt > 0 && claimedAt == 0;
  public int PreviewCoinAmount => rewardPreview?.currencies?.game ?? 0;
}

Server Processing: 
// QuestEngine.processEventInternal()
1. Load config + user state
2. For each unlocked quest:
   - Check step.eventType == "quiz_win"
   - Check filterField "topic" == "anime"
   - Increment step.count (3→4)
   - If count >= requiredCount (10): mark completed
3. Save state (Phase 2)
4. If completed: grant reward (Phase 3)

4️⃣ Quest Completes → Auto-Grant Rewards

Nakama Server RewardEngine.grantReward()

This is where ALL reward types are actually granted — currencies, items, energy, gifts, modifiers

RewardEngine Flow: 
// build/index.js:78406-78472
function grantReward(nk, logger, ctx, userId, gameId, resolved) {
  // 1. Currencies → Wallet
  WalletHelpers.addCurrency(nk, userId, gameId, "game", 1000);
  WalletHelpers.addCurrency(nk, userId, gameId, "xp", 500);
  
  // 2. Items → Inventory
  HiroInventory.grantItem(nk, userId, "badge_weekly_champion", 1);
  
  // 3. Energy → Energy System
  // HiroEnergy.addEnergy(nk, userId, "stamina", 5);
  
  // 4. Gifts → Pending Claims Queue
  Storage.writeJson("gift_claims", "pending_" + userId, {
    claims: [{ claimId: "...", giftId: "amazon_25", type: "voucher", value: "25", status: "pending" }]
  });
  
  // 5. Modifiers → EventBus
  EventBus.emit(REWARD_GRANTED, { userId, reward: resolved });
}
Supported Reward Types:
💰Game Currency (game, tokens, coins)
⚡XP (experience points)
🌐Global Currency (global, xut)
🎒Inventory Items (skins, badges, powerups)
🔋Energy Refills (stamina, hearts, tickets)
🎁Gift Cards/Vouchers (email delivery)
📈Modifiers (XP boost, energy regen)

🪣 Your Use Case: Quest Bucket with Free Product Rewards

Architecture

1. Admin creates "Quest Bucket" — 50+ quests in qv_quest_config with category="bucket"

2. Player sees available quests — quest_engine_get returns all unlocked bucket quests

3. Player chooses up to maxConcurrent — UI shows quest cards, player taps "Start Quest" (requiresOptIn=true)

4. Progress tracked server-side — RecordEvent("bucket_progress", 1, { questId: "chosen_quest" })

5. On completion → Free Product — Gift reward with type="voucher" or type="digital" (assetUrl = product download)

Example Config

{
  "quests": {
    "bucket_free_skin": {
      "id": "bucket_free_skin",
      "name": "Unlock Legendary Skin",
      "category": "bucket",
      "enabled": true,
      "requiresOptIn": true,
      "maxConcurrent": 3,
      "repeatable": false,
      "hidden": false,
      "steps": [{ "id": "s1", "eventType": "bucket_progress", "requiredCount": 50, "filterField": "questId", "filterValue": "bucket_free_skin" }],
      "reward": {
        "guaranteed": {
          "items": { "skin_legendary_dragon": 1 },
          "gifts": [{ "id": "skin_dragon_download", "type": "digital", "assetUrl": "https://cdn.quizverse.com/skins/dragon.glb", "name": "Dragon Skin 3D Model", "deliverEmail": true }]
        }
      }
    },
    "bucket_giftcard": {
      "id": "bucket_giftcard",
      "name": "Earn $10 Gift Card",
      "category": "bucket",
      "repeatable": true,
      "resetIntervalSec": 604800,
      "steps": [{ "id": "s1", "eventType": "bucket_progress", "requiredCount": 100, "filterField": "questId", "filterValue": "bucket_giftcard" }],
      "reward": {
        "guaranteed": {
          "gifts": [{ "id": "amazon_10", "type": "voucher", "value": "10", "name": "$10 Amazon", "deliverEmail": true }]
        }
      }
    }
  }
}

💡 Key Implementation Notes

  • • Use filterField + filterValue on steps to isolate progress per quest in the bucket
  • • hidden: true for surprise quests (revealed only after completion)
  • • enabled: false to soft-disable a quest without deleting it
  • • requiresOptIn + maxConcurrent for "choose your own quest" bucket systems
  • • prerequisiteIds to chain quests (complete A → unlock B)
  • • Gift assetUrl points to S3/CDN for digital products; email template handles delivery
  • • repeatable + resetIntervalSec for weekly/monthly bucket quests
  • • Client calls RecordEvent("bucket_progress", 1, { questId: "..." }) — server does the filtering

✅ Best Practices & Proper Usage

1 Quest Design

  • • Use category (daily/weekly/monthly) for auto-reset
  • • Use resetIntervalSec for custom periods (friend quests)
  • • filterField/filterValue on steps for topic/mode filtering
  • • prerequisiteIds for quest chains
  • • hidden: true for surprise rewards

2 Reward Config

  • • Always use guaranteed for predictable rewards
  • • Use weighted for loot-box style (maxRolls: 1)
  • • Gift deliverEmail: true needs Notifuse config
  • • assetUrl must be accessible (S3/CDN)
  • • Test with reward_catalog_admin_save first

3 Client Integration

  • • Call LoadQuests() on app start + login
  • • RecordEvent() immediately after action
  • • Debounce reloads (400ms in QuestEngineManager)
  • • Use HasUnclaimedReward for popup triggers
  • • Always RefreshWalletAsync() after claim

4 Event Types

  • • quiz_win — quiz victory
  • • quiz_completed — any quiz finish
  • • perfect_round — 100% accuracy
  • • score_shared — social share
  • • friend_challenged — sent challenge
  • • daily_quiz_complete — daily quiz
  • • guild_joined — joined guild
  • • bucket_progress — custom bucket quests

5 Security

  • • Admin RPCs require Server Key (http_key)
  • • User state: permissionWrite: 0 (server-only)
  • • Claim uses OCC version CAS (3 retries)
  • • Gift claims queued — no client-side minting
  • • Metadata validated server-side via filterField

6 Debugging

  • • Check qv_quests storage for player state
  • • Check qv_quest_config for catalog
  • • Check qx_reward_deliveries for history
  • • Check gift_claims/pending_{uid} for gifts
  • • Nakama logs: [QuestEngine] prefix
