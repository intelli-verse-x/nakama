End-to-end sequence

Keep rendering independent from network latency: hydrate disk first, then refresh in the background.

1 · AuthenticateDeviceCreate/restore ISession; bind all cache data to session.UserId.
2 · get_stagedFetch 3 adaptive READY sets and atomically persist the self-contained payload.
3 · hydrate + renderRead memory, then encrypted disk. Render set 1 and prefetch media for set 2.
4 · consume_setAfter play, mark set consumed server-side and trigger refill.
5 · quiz_submit_resultSend score, answer history, timing, and seen IDs after the completed quiz.
6 · aahaa_getCall with generate:true so post-quiz insights include this result.
7 · route surfaceRender by surface; obey fullscreen and rating gates.
8 · aahaa_reactReport shown, clicked, dismissed, converted, or muted.

Current production · LIVE

sets[]: set_id, mode, topic, difficulty_target, question_ids, questions, fresh_count, review_count, status.

questions[]: id, question, options, correct_index, explanation, difficulty, category/topic/mode, media_url, media_provenance, media_alt, citation, quality, review (semantic + experience checks), source, country_codes, behavior_tags, selection_reasons.

adaptive: basis, accuracy_pct, sample_size, target_difficulty.

personalization.geo: ISO country or GLOBAL, basis, 60% desired blend, actual relevant/global counts, fallback reason. personalization.behavior: persisted-history basis, signals, samples, weaknesses/misses/latency, and unsupported future signals.

repeat_policy: fresh_count, review_count, pool_exhausted, content_generation_queued, next_refresh_eta_seconds.

suppress_rating_prompt: blocks native store review prompts when true.

Three sets are currently returned for want_sets:3; treat two as the minimum usable online depth.

QuizContentService.cs (concise pseudocode) 
using Nakama;
using Newtonsoft.Json;
using System.Threading.Tasks;

public sealed class QuizContentService {
  readonly IClient client; ISession session; readonly IEncryptedCache disk;
  SeedQResponse memory;

  public async Task<SeedQResponse> Start(IClient c, ISession s, string mode, string topic) {
    client = c; session = s;
    memory = disk.ReadValid<SeedQResponse>(Key(s.UserId, mode, topic));
    _ = Refresh(mode, topic);                 // background; hydrated data can render now
    return memory;
  }

  async Task Refresh(string mode, string topic) {
    var payload = JsonConvert.SerializeObject(new {
      mode, topic, set_size = 6, want_sets = 3
    });
    var rpc = await client.RpcAsync(session, "quizverse_seedq_get_staged", payload);
    var next = JsonConvert.DeserializeObject<SeedQResponse>(rpc.Payload);
    Validate(next, session.UserId, mode, topic); // IDs, answers, owner, schema, expiry
    disk.AtomicWriteEncrypted(Key(session.UserId, mode, topic), next);
    memory = next;
    PrefetchMedia(next.sets.Length > 1 ? next.sets[1] : next.sets[0]);
  }

  public async Task Complete(SeedQSet set, object result) {
    await client.RpcAsync(session, "quizverse_seedq_consume_set",
      JsonConvert.SerializeObject(new { mode=set.mode, topic=set.topic, set_id=set.set_id }));
    await client.RpcAsync(session, "quiz_submit_result", JsonConvert.SerializeObject(result));
    var feedRpc = await client.RpcAsync(session, "quizverse_aahaa_get", "{\"generate\":true}");
    Route(JsonConvert.DeserializeObject<AahaaFeed>(feedRpc.Payload));
    _ = Refresh(set.mode, set.topic);          // refill at low watermark (< 2 ready)
  }

  public Task React(string id, string action, bool fullscreen=false) =>
    client.RpcAsync(session, "quizverse_aahaa_react",
      JsonConvert.SerializeObject(new { wow_id=id, action, fullscreen }));

  public void Logout() { disk.DeleteAllForUser(session.UserId); memory=null; session=null; }
}

Persistent cache requirements

Identity and isolation

Key every record by userID/canonicalMode/topic/country-or-global. Never share cached sets between accounts, countries, guest conversions, or environments. Delete the previous user's namespace at logout.

Safe persistence

Encrypt at rest because answer keys are included. Write a temp file, flush, then atomic rename. Include client schema/version and reject unknown/newer schemas.

Expiry and hydration

On startup, hydrate valid disk data into memory before network refresh. When live metadata arrives, enforce expires_ms; before then use a conservative client TTL.

Depth and refill

Target 3 ready sets. Continue with 2; refill in background whenever unconsumed depth drops below 2. Never mark consumed locally as playable again.

Media

Prefetch the next set's media_url, cache by URL/hash, cap storage, and time out quickly. If media fails, use a neutral placeholder or a text-safe question layout—do not block the quiz.

Validation

Require unique IDs, ≥2 options, in-range correct_index, quality.status=approved, review.reviewed=true, non-empty semantic and experience checks, matching mode/topic/country, and no consumed IDs. Reject the whole envelope on ownership/schema corruption.

Product behavior that must stay honest

Smart Review and exhaustion

Render “N new + M Smart Review” directly from repeat_policy. Mark each questions[].recycled == true item as review. Never imply it is new.

If pool_exhausted, show a refill/recommended-topic message; use content_generation_queued and ETA only as status, not a guarantee.

Rating prompt gate

Only invoke iOS/Play native review when both are false:

Gate 
allowRating =
  !seedq.suppress_rating_prompt &&
  !aahaa.rating_prompt_suppressed;

Aahaa surface routing

PersonalizedHomeUI → home hero; EndOfQuizReviewScreen → post-quiz card; MilestoneCelebrationScreen → fullscreen; MidQuizToast → native toast; AIFortuneTeller → fortune screen only.

Always display signal as “Why this appeared.” Send shown once actually visible, then the user's terminal action.

Fallback and rollout order

  1. Unconsumed, valid in-memory staged set.
  2. Encrypted, valid disk staged set.
  3. quizverse_seedq_get_staged.
  4. Legacy S3 path via quizverse_request_questions / deduped_s3.
  5. Bundled emergency pack with explicit offline copy.

Remote-config: seedq_staged_enabled, percentage cohort, kill switch, minimum app version, cache TTL override. Ramp internal → 5% → 25% → 100%, watching RPC errors, fallback rate, empty depth, media failures, and repeat disclosures.

Integration acceptance checklist

Run once per platform and for guest, returning, and account-switch personas.

  • Device auth creates/restores an ISession; cache namespace equals session.UserId.
  • Fresh online launch returns 3 distinct sets; set 1 renders while sets 2–3 remain ready.
  • Airplane-mode relaunch hydrates a valid encrypted set without cross-account leakage.
  • Atomic-write interruption leaves either the previous valid file or the new valid file—never partial JSON.
  • Expired, wrong-user, wrong-schema, malformed-answer, and duplicate-ID caches are rejected.
  • Consume set, fetch/refill, and assert zero overlap with consumed IDs while fresh pool remains.
  • Depth below 2 starts one background refill (no request stampede).
  • Review items show “Smart Review”; fresh/review totals equal questions served.
  • Pool exhaustion shows honest copy and suppresses native rating prompts.
  • Media prefetch succeeds; timeout/404 uses fallback without blocking interaction.
  • quiz_submit_result sends score, history, timing, and seen IDs exactly once/retry-idempotently.
  • Post-quiz aahaa_get(generate:true) routes each surface and displays signal lineage.
  • Every rendered wow sends shown; CTA/dismiss/mute sends the matching reaction.
  • Remote kill switch immediately returns the app to legacy fallback without deleting valid staged cache.
  • Logout deletes memory and disk cache; next account cannot see previous questions or answers.
Fast verification: use the live verifier for backend evidence, then run the device-level cases above in the Unity Test Framework and on physical iOS/Android devices.
